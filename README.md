# otogaki（音書き）— 音楽ドラフト帳

頭にうかんだ曲のアイデアを「紙に書き出す感覚」でドラフトにするコンパクトな DAW。
高度な機能はない。作曲・コード・アレンジのアイデアをさっと形にするための道具。

## 起動

```bash
nix run
```

初回はツールチェーン取得と npm install で少し待つ。ブラウザが開いたら準備完了。

## できること

- **セクション構成**: Aメロ・サビなどのブロックを並べて、各セクションにメモ（「ここは切なく」等）と、キー・拍子を残せる（転調や拍子変更はセクションを割って表現する）。キーはメジャー/マイナーの他、ドリアン・フリジアン・リディアン・ミクソリディアン・ロクリアン・ハーモニックマイナーといった教会旋法も選べる
- **コード進行と度数**: `C | G/B | Am7 | F` のようにテキストで書くだけでパースされ、再生するとそのまま鳴る。`|` が小節区切りで、改行は無視される。再生中は今鳴っているコードがハイライトされ、各コードの下にその小節のキー（教会旋法も含む）に対する度数（I, V7, vi など）が小さく表示される。編集面はモーダルではなくコードトラック画面に直接展開（ボタンで開閉）されるので、ループ再生しながら書き換えて音の違いを即座に確かめられる。ブロック表示⇔ライン表示の切替えも可能
- **リズムプリセット**: コードトラックに「リズム:」で 8ビート・16ビート・フォーク・アルペジオ（分散）・全音符・シンコペーションを選べば、ベタうちではなく刻んだリズムで再生される。実際に鳴る MIDI ノートとその強弱（ベロシティ）はピアノロール上にプレビュー表示される（読み取り専用）
- **ピアノロール**: クリックでノート配置、ドラッグで伸ばす・移動、右クリックで削除。1/16 スナップ。セクションにキーを設定すると、背景でスケール外の行が薄く暗くなる（雑に置いても外れにくいように）。カットツール（`c`）でノートを分割し、`g` で隣接する選択ノートを結合（カットの逆操作）できる
- **ギター表示**: コード進行パネルで 🎸/🎹 を切り替えると、指板の実際の運指がリアルタイムに表示される。よく使う運指は名前付きで登録（ボイシング辞書）でき、再生にも反映される
- **複数トラック**: ピアノ・アコギ・ベースは SoundFont、ドラムは TR-808、仮メロはシンセ（即発音）。トラック名・音量・ミュートを個別に調整
- **ドラムパターン**: 8ビート・16ビート・4つ打ち・バラードをワンクリック配置。ステップグリッドとピアノロールを切替えられる
- **ループ再生**: 「ループ: オフ / 全体 / セクション」を選んでおけば、あとは Space だけでそのモードの再生になる
- **断片棚**: 思いついたフレーズを名前付きで退避しておき、あとで好きな位置に配置できる。曲を頭から順に作らなくていい
- **参考オーディオ**: 耳コピ用に音楽ファイルを読み込んで同時再生。波形をピアノロールの上に並べて表示し、オフセット（ms）で拍を合わせられる
- **元に戻す / やり直し**: Ctrl/Cmd+Z、Shift を付けるとやり直し。連続した入力やドラッグは 1 ステップにまとまる
- **曲全体メモ**: BPM の隣に小さなテキストエリア。雰囲気・参考曲など、1曲に1つだけのメモを持てる
- **ダークモード**: ツールバーのトグルで OS設定自動追従 / ライト / ダークを循環。選択は次回起動時も保持される
- **保存**: localStorage に自動保存（1秒 debounce）。選択中トラックも残るのでリロードしても同じトラックから再開できる。JSON 書出/読込でファイルにも残せる
- **MIDI 書出**: ドラフトを .mid で書き出して本物の DAW に持っていける
- **WAV 書出**: 選んだ範囲を音声ファイルとして書き出し、そのまま共有できる

## キーボード

主要なもののみ。全一覧はアプリ内の「? ショートカット一覧」ボタン（または `?` キー）で確認できる。

| キー | 動作 |
|------|------|
| Space | 再生 / 停止 |
| Ctrl/Cmd+Z | 元に戻す（+Shift でやり直し） |
| Delete | 選択ノートを削除 |
| Ctrl/Cmd+C / X / V | コピー / カット / 貼付 |
| c / g | カットツール切替 / 隣接ノートをマージ |
| [ / ] | ループ範囲の開始 / 終了を設定 |
| Escape | 選択解除、開いているモーダルを閉じる |

## 開発

```bash
nix develop            # devShell（elm / elm-format / elm-test / node）
npx vite dev           # dev サーバ
elm-test               # テスト
npx vite build          # プロダクションビルド
```

### 設計メモ

- Elm は「楽譜の編集器」、JS（Tone.js + smplr）は「演奏者」。再生時にフラットなイベント列を port で一括送信する
- 時間は PPQ=480 の Ticks（整数）に統一。秒への変換は JS 側の仕事
- コード展開もドラム展開も Elm の純関数（`Codec/Performance.elm`）。再生と MIDI 書出は同じ展開を通るので内容が一致する
- アンドゥは Project スナップショットのスタック（最大 100 件）。update ラッパーが project の変化を検知して自動で積むので、新しい編集操作を足しても対応不要
- セクション列から「曲の小節表」（`Data/Timeline.elm`）を作り、小節番号↔ticksの変換・拍子・キーの参照は全てここに集約する。既存ノートの終端・セクション合計のどちらよりも常に余白分長くしてあるので、グリッドの外側に音を置けない壁にならない
- 参考オーディオの音声データは保存しない（localStorage の容量制限）。ファイル名とオフセットなどの設定だけ残る
- 音源サンプルは smplr の CDN（jsDelivr）から遅延ロード。オフライン化したくなったら smplr の baseUrl をローカルに差し替える

## やらないこと

オーディオ録音、エフェクト、ミキシング、オートメーション、曲中テンポチェンジ。
ドラフトが育ったら本物の DAW へ。
